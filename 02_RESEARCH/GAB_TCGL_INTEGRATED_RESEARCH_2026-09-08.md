## 1. Outcome, provenance, and correction

Working objective: maximize useful autonomous work within authorized limits while minimizing avoidable human supervision, rework, and unapproved effects.

**GAB identifies where judgment is needed. The user-authority gate identifies where permission must change. They must not be collapsed.** Agents can reason extensively within an existing grant. Uncertainty alone does not transfer a decision to the user.

TCGL provides the proposed knowledge-development loop: Theory → Provisional investigation → explicitly user-authorized Probational implementation → evidence and authorized disposition → possible Canon. Agents contribute governance intelligence; the user retains governance authority.

This synthesis combines the initial feedback-loop mission, both TCGL installments, and the latest Governance Research Direction. It supersedes conflicting recommendations in [the historical TCGL report](TCGL_GOVERNANCE_LIFECYCLE_RESEARCH_2026-09-08.md).

- Agents may autonomously promote **Theory → Provisional**, with justification, task provenance, expected benefits/consequences, evidence, uncertainty, and scope.
- **Provisional → Probational requires explicit user authorization.** The earlier recommendation for autonomous adoption under generic experimental envelopes is withdrawn.
- The user has not approved every reverse transition or rejection power previously bundled with autonomous curation.
- Agents can carry out the specifically approved experiment without repeatedly asking for unchanged permissions. This does not authorize a new candidate, altered policy, expanded scope, or unapproved renewal.
- Automatic shutdown/recovery remains a term to specify in each actual trial plan, not a power conferred by this research.

## 3. Tightening GAB without defeating its purpose

Three corrections strengthen the user's theory.

**First: GAB is contextual.** It depends on the current task, authorized effects, available information, model/tool capabilities, environment, and time. The same decision may be deterministic in one workflow, safely inferential in another, and reserved in a third.

**Second: choosing one action does not prove it is legitimate or correct.** A rigid but mistaken rule can leave exactly one bad choice. Determinism reduces variability; separate validation determines whether the mechanism implements the intended rule.

**Third: narrowing is not always improvement.** Overconstraining an agent can block useful solutions, increase workarounds, or transfer routine work back to the user. Evaluate outcomes and burden, not merely how few branches remain.

Working terminology:
- **Autonomy:** discretion among already-authorized choices.
- **Governance authority:** power to alter permissions or governing requirements.
- **Action authorization:** the actual grant needed to perform a specific effect.
- **GAB:** the region requiring judgment after applicable structure is considered.
- **User gate:** a decision reserved to the user, including Provisional → Probational.
- **Observation:** something recorded; interpretation and proposed remedies remain distinguishable.

“Authority” has broader meanings in access-control literature; using “governance authority” avoids teaching that an autonomous agent has no authorization at all.

## 4. A usable boundary model

For a task at a particular moment, let the permitted action set be the actions consistent with applicable higher rules, the current grant, resources, and observed preconditions. This is a conceptual model: natural-language obligations are not assumed fully computable.

Agent discretion selects within that set. Better tools can reveal facts or enforce adopted limits; they do not silently enlarge the set. A new user decision can change the applicable grant.

| Authorization | Judgment/information needed | Appropriate handling |
| --- | --- | --- |
| Known and sufficient | Rule is clear and inputs available | Execute using the rule/control. |
| Known and sufficient | Several legitimate approaches remain | Infer and choose within task criteria; inspect more evidence when useful. |
| Unclear | Missing authority facts can be checked | Retrieve the actual grant or authoritative policy; do not ask the user to reconstruct accessible records. |
| Insufficient or user-reserved | Regardless of agent confidence | Prepare a recommendation or explain the blocked effect; obtain the required decision. |
| Prohibited by an applicable non-overridable rule | Regardless of usefulness | Do not execute. A user question is not an automatic override mechanism. |

Missing factual input can justify a clarification question without being a governance-approval question. Conversely, an agent can know exactly what it wants to do and still lack permission.

Do not freeze unrelated work while awaiting a decision. Continue authorized independent tasks and preserve the blocked dependency. Silence, elapsed time, or absence of objections cannot authorize a protected action.

## 5. The five routes are complementary mechanisms

| Route | Function | Example | Main check |
| --- | --- | --- | --- |
| Deterministic enforcement | Evaluate explicit conditions and mediate effects. | Refuse a write outside the allowed resource set. | Coverage, correctness, and current inputs. |
| Instructional governance | Explain objectives, obligations, and applicable defaults. | Use the task's specified success criterion. | Ambiguity, conflicting text, and actual applicability. |
| Bounded agent inference | Choose means within existing authorization. | Select between two permitted research methods. | Stay within effects, resources, and quality requirements. |
| Agent recommendation | Prepare a decision it cannot authorize. | Propose a particular governance experiment. | Evidence for/against and scope are visible. |
| User authority | Decide a reserved change. | Authorize that Provisional candidate's Probational trial. | Exact candidate, terms, and consequences are understood. |

A single action can use all five at different times. They are not a ladder on which everything must eventually reach the user.

Apply the funnel repeatedly: establish scope → inspect facts → use rules/tools → choose within the grant → recheck permission immediately before consequential effects → observe result. Branching can recur after each tool result.

## 6. TCGL integrated precisely

| Stage/transition | Current meaning and permission |
| --- | --- |
| Theory | Idea pool; no governing authority. Preserve useful material without pretending it is established. |
| Theory → Provisional | Agent may curate autonomously with the user's required provenance. This spends only already-authorized task attention/resources. |
| Provisional | Investigate hypothetical implementation, interactions, costs, risks, authority, reversibility, and measurement. Do not operate under the proposed rule. |
| Provisional → Probational | Explicit user authorization of the candidate and bounded plan. Agents recommend; they do not decide this transition. |
| Probational | Actual bounded implementation with stronger evidence and review. Agents execute and observe within the approved plan. |
| Probational → Canon | Operational evidence plus authorized durable adoption; WISDOM canon requires explicit Operator decision. |
| Backward/revised movement | Preserve reasons and history. Agents recommend; operational and governance transitions require their applicable authority. |
| Canon → reconsideration | Investigate a successor while existing canon remains effective until properly amended or suspended. |

Track **maturity, authorization, and activation separately**:
- Approval to start is not proof a trial started.
- An approved-but-not-started candidate remains Provisional with a pending activation record.
- Partial activation is an incident state, not a clean success or non-event.
- Expiration stops the permission according to its terms; it need not imply the hypothesis is false.
- Demotion does not undo effects; record verified shutdown/recovery separately.
- A revised candidate gets a new revision and review of applicable approval.
- Wider or different scope gets a linked applicability record and its own required decision.

Avoid making every ordinary task choice a governance transition. A newly chosen search method inside an authorized research task is ordinary inference. Instituting “always use this method” as a proposed governing default is a policy claim. Once a candidate is being deliberately applied as a TCGL governance experiment, sandbox location or one-time use does not bypass the user gate.

This distinction is a research design recommendation; borderline cases should record which governing obligation, permission, or future default would actually change.

## 7. Agents as distributed observers of governance quality

This is an experimental proposition, not an established capability guarantee.

Proposed workflow:
1. Agent notices a material event during owned work.
2. It records the observation separately from its explanation.
3. It links an existing candidate or curates a new Provisional record with the required justification.
4. Other authorized tasks can contribute observations under their own identities and scopes.
5. A synthesis process retains counterevidence, identifies duplicated sources, and proposes the next useful investigation.
6. When a concrete trial is justified, it prepares one decision packet for the user.
7. After user authorization, execution contributes actual trial evidence; disposition remains governed.

The research store is not a permission store. Agents may contribute only data they are authorized to access and share. Publishing or cross-project transfer needs the appropriate destination/access authority. This report contains the general method, not private source-project records.

Agent reports are observations by fallible participants, not neutral sensors by definition. Risks include self-justification, common-model bias, omitted failures, copied evidence, misclassified interruptions, and attractive but unsupported causal explanations. Preserve tool receipts and independent outcome checks where available.

Different agents repeating one underlying event do not create independent replication. Store source-event identity. Preserve disagreement instead of averaging it into apparent consensus. A synthesis agent cannot acquire promotion authority by becoming the aggregator.

## 8. Minimum records and repository design

Start with short human-readable cards; automate identifiers and version capture when worthwhile.

| Record | Essential content |
| --- | --- |
| Boundary record | Decision type; owning task; allowed effects; constraints; authoritative references; autonomous choices; user-reserved changes; evidence needed. |
| Provisional card | Candidate/revision; reason selected; originating task; expected benefits/consequences; evidence and counterevidence; uncertainty; scope; next investigation. |
| Observation | Event/run ID; task; reporter; configuration/model/tool identities where known; facts; evidence reference; intervention and reason; interpretation separately. |
| Decision packet | Exact proposed change; alternatives; evidence for/against; effects; risks; scope; success/failure measures; trial limits; rollback; user decision requested. |
| Trial receipt | User approval reference; candidate/version; actual start/configuration; affected resources/agents; outcomes; stop/recovery; review disposition. |

Retain exact policy/instruction versions where available and mark hidden or unknown state honestly. Store snapshots once and reference them. Record enough successful autonomous decisions to detect missed escalation; logging only interventions creates a blind spot.

For a future shared dump: stable concept IDs, append-only observation history with corrections, scope-specific applicability, explicit supersession, and links to each project's authorized adoption record. Avoid copying active policy text into every research note. A copied source-canonical label remains about the source scope.

Keep concurrency controls proportional: expected-version checks and unique event IDs can prevent lost updates and duplicate transitions. Hashes establish byte identity, not legitimate authority.

## 9. User intervention as a two-sided measure

The objective is reduced *total supervision burden at acceptable quality and authorized risk*, not the smallest question count.

| Measure | Proposed denominator or interpretation |
| --- | --- |
| Unnecessary interruption rate | Avoidable interruptions / decisions independently judged executable under existing authority and available information. |
| Missed required escalation rate | Unescalated reserved decisions / all reviewed decisions requiring escalation. |
| Verified completion | Correct, authorized results / attempted tasks; include failures and abandonment. |
| Human burden | Review, clarification, approval, repair, and context-reconstruction time. |
| Recovery quality | Successful verified recoveries / required recovery attempts; include partial/failed recovery. |
| Observation usefulness | Supported, decision-relevant observations / reviewed observations, plus recording/synthesis cost. |
| Coverage | Missing task/event records and sampled autonomous actions, not just the number of logs collected. |

A reviewer may label a decision indeterminate; do not force uncertain cases into “unnecessary.” Separate factual clarification, permission request, preference elicitation, failure recovery, and status update.

Track severity and raw counts alongside rates. Few observed harmful events cannot establish a low true risk in a small sample. User approval time is not automatically waste: TCGL's adoption gate is an intended control.

Repeated interruption → inspect reason → compare candidate fixes. Possible fixes include a tool, better input, clearer rule, a user-approved default, or different task structure. The correct remedy need not be more policy or more autonomy.

Human oversight design must also test whether the user can reconstruct current state and intervene effectively after a long autonomous interval. “Human on the loop” should describe actual information, controls, and response ability rather than a reassuring label.

## 10. Failure cases that should defeat naive versions

Analytical cases below have not been executed as a software benchmark.

| Case | Required response / lesson |
| --- | --- |
| Two authorized methods remain | Choose within task criteria; do not escalate merely because there are two options. |
| Only one action remains but its authorization is absent | One obvious action is not permission. |
| Policy text is clear but a tool permits prohibited effects | Instructional clarity does not establish enforcement. |
| Agent declares itself sufficiently confident to activate a Provisional rule | User gate remains required. |
| Prior approval covers another candidate or scope | Do not reuse it as authority for this trial. |
| Agent follows a specifically approved trial's unchanged steps | Proceed without repetitive permission requests. |
| Agent quietly applies a candidate to gather “provisional evidence” | Unapproved implementation; preserve the incident rather than legitimize it retrospectively. |
| Generic “reversible experiments allowed” language | Cannot replace explicit user authorization of a Provisional → Probational transition under the current clarification. |
| Stale policy/grant after revocation | Revalidate before effects; queued work does not retain unlimited authority. |
| Many individually permitted actions exceed a cumulative limit | Check aggregate effects, resources, and interacting tasks. |
| Provisional folder floods with near-duplicates | Improve curation/deduplication; promotion count is not performance. |
| Agent marks a failed trial demoted while changes remain | Keep recovery unresolved and follow approved containment. |
| User is unavailable | Continue independent authorized work; hold reserved effects. |
| Lower interruption count hides unauthorized actions or worse quality | Reject the apparent improvement. |
| Safeguards cost more than the failures they prevent | Simplify after evidence and appropriate approval, without erasing necessary boundaries. |
| A new model is worse at recognizing the same boundary | Reassess applicable discretion and controls; text alone does not guarantee equivalent behavior. |

## 11. Concrete path to testing the theory

First investigate retrospectively using records already authorized for research. Identify recurring decision types and compare agent explanations with actual grants/outcomes. This task permits analysis; it does not authorize executing new governance policies.

Prepare a proposed bounded pilot:
- Candidate: a task-bound decision-routing card distinguishing deterministic handling, inference within existing authority, and reserved recommendations.
- Scope: disposable sample-file organization and a separate source-comparison task; no private project material, external writes, credential changes, or new spending.
- Baseline: the same basic permissions, tools, and success criteria without the routing card.
- Treatment: the routing card plus structured observation records; permission itself stays matched so improved clarity is not confused with larger grants.
- Trials: use matched task sets, counterbalanced order, multiple runs, held-out boundary cases, and eventually additional beginners. Select actual counts and resource caps in the concrete approval packet.
- Measures: verified completion, avoidable interventions, missed required escalation, total human/work cost, and record usefulness.
- Guardrails: any authority violation or loss of essential evidence stops further experimental effects under the approved plan.
- Recovery: specify exactly which disposable artifacts may be restored, how in-flight work ends, and how recovery is verified.
- Review: compare both benefits and harms with configuration labels hidden where practical; keep unknowns and failed runs.
- Decision: user accepts, revises, or rejects the trial proposal before treatment affects execution.

Test the distributed-observer hypothesis separately: first compare observation quality with a reviewer-labelled record set. Then, only in a specifically authorized pilot, assess live capture overhead and missed events. This separates observation quality from the effects of changed governance.

Falsification conditions: no better decision accuracy or outcomes at comparable authority; increased missed escalation; burdensome records; failure to transfer to new tasks; or an ordinary tool/input repair explaining the benefit better than the governance change.

Do not manufacture precision. Numeric benefit thresholds, sample size, time limit, and reviewer availability require actual pilot context; the draft is not launch-ready without those fields and explicit user approval.

## 12. Tooling design after approval

Proposed progression:
1. Record validator and index: validate required fields, versions, provenance, and contradictory status/activation claims.
2. Decision support: assemble concise user packets with source links and unresolved facts.
3. Runtime integration: existing authorization boundary mediates actions; approved trial identity and scope travel with execution receipts.
4. Expiry/revocation/recovery: enforce the actual trial terms and reconcile partial outcomes.

Deterministic tooling should handle known predicates, deduplication, identity, version comparison, aggregate limits, and receipt collection. Agents handle contextual diagnosis, alternative generation, synthesis, and recommendations. The user handles reserved adoption and protected changes.

A tool cannot safely infer its own policy-making mandate from research text. The promoter and evidence producer should not unilaterally rewrite the evaluator, acceptance criteria, or authority records. These are planned properties, not claims about installed software.

## 13. Full class-production chain

The project remains in research/class-architecture development. The following are candidates, not fixed course lessons.

| Stage | Work product | Advancement evidence |
| --- | --- | --- |
| Research | Source crosswalk, observations, counterexamples, scoped hypotheses. | Claims distinguish fact, analogy, and experiment. |
| Project architecture/governance | Map decision owners, grants, information flows, and action controls. | One real workflow can be traced without hidden authority assumptions. |
| Engineering methodology/task structure | Identify significant recurring boundaries and success measures. | Less avoidable work without reduced quality or increased unauthorized effects. |
| Agent instructions/tools | Teach and support the five routes with scoped authority references. | Boundary cases pass; stale grants and missing evidence are visible. |
| Curriculum architecture | Begin from learners' useful goals and introduce needed distinctions progressively. | Prerequisites and burden fit beginners. |
| Lessons/exercises | Contrast ordinary choice, curation, recommendation, authorization, and execution. | Learner explains the difference using evidence, not labels alone. |
| Student projects | Run an explicitly authorized bounded experiment on a personally useful workflow. | Traceable outcomes, honest limits, and recovery/disposition. |
| Assessment | Evaluate scope, evidence, judgment, escalation, and justified rejection. | Independent performance on unfamiliar cases. |
| Finished class | Adopt supported teaching practices and version material. | Additional learner evidence, transfer, and instructor review. |
| Curriculum feedback | Preserve misconceptions, interventions, outcomes, and lesson versions. | A proposed revision improves learning without hiding added burden. |

Candidate exercise pairs:
- Choosing a permitted tool versus granting permission to a new tool.
- Curating a promising idea versus running its policy.
- Missing data versus missing authorization.
- Executing approved trial steps versus changing the experiment.
- Reporting contradictory evidence versus repealing Canon.
- Fewer questions with preserved quality versus fewer questions achieved by silent overreach.

Proposed assessment: score correct scope, applicable authority, evidence quality, choice/escalation reasoning, and treatment of uncertainty/recovery. Reward a justified “do not promote.” Do not reward maximal autonomy, policy length, or promotion count.

For beginners, start with three questions: What can the agent decide? What must it ask me? What evidence will tell us whether that division works? Add identifiers, logging, delegation, and policy-as-code when a learner's project needs them.

The class itself can demonstrate TCGL: reason about a teaching approach, investigate feasibility, request authorization for an actual teaching pilot, observe learners, and adopt or reject based on evidence. Label hypothetical classroom cases separately from real learner trials.
