# First Hands-On Agent Architecture — Provisional Blueprint

**Date:** 2026-09-06
**Status:** PROVISIONAL
**Area:** curriculum architecture / classroom experiment
**Authority:** noncanonical unless explicitly promoted by the Operator
**Origin:** W.I.S.D.O.M. brainstorming thread, 2026-09-06

## Purpose

Preserve a surviving candidate for an early hands-on classroom progression without treating it as settled curriculum.

The intended educational question is not whether more agents are inherently better. It is whether a learner can directly observe what changes when coordination, delegation, and peer/parallel agent work are introduced one layer at a time.

## Candidate progression

### Stage 0 — Project foundation

Before the agent comparison, the learner has a durable project/repository and has already been introduced to a lightweight constitutional posture: human authority, boundaries, explicit adoption, evidence, and responsibility.

A large formal constitution is not currently proposed as a prerequisite to first practical work.

### Stage 1 — Primary Coordinator alone

Create the basic Primary Coordinator skeleton.

Let the learner use and experiment with it as a single-agent system.

This supplies the baseline for later comparison.

### Stage 2 — Coordinator + one worker

Add one delegated worker agent.

Observe Coordinator/worker cooperation, delegation, context transfer, returned evidence, correction, and escalation.

### Stage 3 — Coordinator + two workers

Add a second worker so the learner can observe both Coordinator-to-worker relationships and the effects of multiple workers operating within one coordinated system.

The purpose is to expose divergence, duplication, conflicting conclusions, complementary work, synthesis burden, and the interconnections required to make the architecture useful.

## Just-in-time constitutional instruction — candidate method

Constitutional principles may be reinforced when the learner encounters the concrete problem that makes a principle relevant.

Candidate examples include small instructional callouts for:

- delegated authority;
- evidence versus assertion;
- explicit adoption;
- policy versus execution;
- unnecessary escalation;
- governance branching or overconstraint.

This remains a teaching hypothesis, not Canon.

## Conditions required for a useful comparison

The stages should use tasks that are comparable enough that the learner can reasonably attribute observed differences to the architecture rather than to a completely different assignment.

The exercise should make room for the possibility that an added agent makes the system worse.

The architecture should remain small enough that setup complexity does not overwhelm the concept being studied.

## Surviving objections and failure modes

This candidate remains vulnerable to the following:

1. **Ceremony risk.** If the task is too simple, additional agents may add process without educational or operational value.
2. **Confounded comparison.** If each stage receives a materially different task, the exercise will not isolate coordination effects.
3. **Invisible benefit.** A strong Coordinator may solve the baseline task so well that the value of delegation is difficult to see.
4. **Complexity overload.** Agent plumbing, tooling, or repository mechanics may consume more attention than the architectural lesson.
5. **Premature architecture teaching.** Learners may need more basic AI-operation fluency before multi-agent relationships become meaningful.
6. **Governance interruption.** Just-in-time constitutional callouts may become distracting or preachy if they fire too often or without a genuine problem.
7. **False generalization.** A three-agent classroom system is a teaching instrument, not proof that real systems should use the same topology.
8. **More-is-better bias.** The lesson fails if students leave assuming agent count is a quality metric.

## Candidate observations

If this becomes Probational, preserve evidence about:

- delegation clarity;
- context-transfer loss;
- duplicate or conflicting work;
- complementary work;
- error propagation and recovery;
- escalation frequency;
- synthesis burden;
- authority-boundary mistakes;
- added control overhead;
- learner ability to explain what changed and why;
- cases where the simpler architecture performs better.

## Promotion boundary

This record should not move beyond Provisional merely because the sequence sounds coherent.

A reasonable path toward Probational status would require a runnable classroom design, controlled/comparable tasks, and an observation plan capable of exposing both benefits and harms.

Canon remains an explicit Operator decision.
